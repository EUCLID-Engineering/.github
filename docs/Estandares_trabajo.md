# 🤝 Estándares de Trabajo (SOP)

Para mantener la "Ingeniería Pura" en cada línea de código, el equipo sigue estas normas obligatorias:

## 1. Convención de Commits

Utilizamos Conventional Commits para que el historial sea legible:

- `feat`: Nuevas funcionalidades.
- `fix`: Corrección de errores.
- `docs`: Cambios en documentación (como este README).
- `style`: Formato y estética sin cambios en lógica.
- `refactor`: Mejora de código existente.
- `chore`: Tareas de mantenimiento (actualizar librerías, etc.).

## 2. Flujo de Desarrollo y Ramas

Las ramas deben ir ligadas a las tareas de gestión:

- `main`: Código estable y funcional.
- `develop`: Integración de nuevas funciones.

- `feature/SCRUM-XX-descripcion`: Para nuevas características.
- `bugfix/SCRUM-XX-descripcion`: Para solución de errores.

## 3. Pull Requests (PR)

Todo código debe ser revisado antes de integrarse. Un PR exitoso debe incluir:

- Breve descripción del cambio.
- Referencia al ID de la tarea (Jira/Scrum).
- Confirmación de pruebas realizadas.
